# v2 acceptance loop (phase 2, 2026-10-19)

The loop PLAN.md section 17 asks for: build each of the twelve visual cases, screenshot it at 1440x900 and 1920x1080 with the conversation panel open, run the checklist in the browser, fix what fails, repeat. The driver is `scripts/accept.mjs` (screenshots plus the checklist, one JSON line per case and viewport and a Markdown table at the end); the bench prompts for the cases are the `v2-accept` group of `scripts/prompts.json`. The server for every round is the branch build on `127.0.0.1:4270` over a copy of `~/.terminal` (`TERMINAL_HOME` under the scratchpad; the JSON store migrated to SQLite on first start: 8 workspaces, 37 widgets), OpenBB 5.0.0 on 6900, Opus 5.5 configured.

Checklist columns (the section 17 list, one letter each in the tables): overflow (no element with `scrollWidth > clientWidth`), holes (no empty grid cell; a cell showing "No data", "Could not load" or a skeleton counts as empty), fill (content at least 60% of a table's or card's body, 80% of a chart's), oneRow (no table with one row), columns (three at 1440 with the panel open), headers (title and sub-header on every widget), charts (legend and last-value label on every chart), clipped (no text clipped mid-word: an ellipsis on text wider than its box, or a text box cut by `overflow: hidden`), verified (the reply's verification has no unverified number), chips (at least one chip, every chip names a widget), plain (no markdown headings, bullets or bold in the reply).

## Round 0: the agent is blocked

`BASE=http://127.0.0.1:4270 node scripts/prompt-bench.mjs --group v2-accept` failed every case in under a second with the Anthropic API's `Your credit balance is too low to access the Anthropic API`. The only LLM credential on the machine is `ANTHROPIC_API_KEY` in `~/terminal/.env` (no OpenAI key, no key in `config.yml`), so no prompt can reach the model until the account is topped up. The rubric half of the loop (answer first, facts complete, numbers verified, right widgets, cites, time window) therefore cannot be graded in this PR; the rendering half can.

What the loop still exercises without the agent: `scripts/accept-cases.mjs` holds the twelve workspaces hand-built from the case descriptions (the recipes, routes and transforms the prompt rules tell the agent to use: the P/E example verbatim, `ot.rsi`/`ot.macd`, `ot.corr`, FINRA bond routes, the screener route, the SMA backtest), and `node scripts/accept.mjs --build` creates them on the server and scores them with the same checklist (the three reply columns read n/a). Every rendering defect found this way is one the agent's workspaces would have shown too.
