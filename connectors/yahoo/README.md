# @terminal/connector-yahoo

Answers `search`, `quote`, `ohlcv`, and `earnings` from Yahoo Finance through [yahoo-finance2](https://github.com/gadicc/node-yahoo-finance2) (pinned, no API key, config `{}`). Search resolves each term to the first US-listed equity or ETF (one call per term, in parallel; a term with no match keeps its row with null symbol, name, and exchange). Quote batches every symbol into one call and maps the live pre- or post-market price into `extended_price` / `extended_change_pct`. OHLCV calls the chart endpoint once per symbol with `period1`/`period2` derived from our range (`1d` starts at New York midnight of the most recent session; weekends and pre-open fall back to the previous weekday), maps `1w` to `1wk`, requests regular-session bars only, drops bars without a close, and emits `time` as epoch milliseconds sorted by symbol then time. Earnings reads `quoteSummary` `calendarEvents` per symbol: next date only, formatted YYYY-MM-DD in New York, `session` always null (Yahoo stamps every date at 20:00Z), `eps_estimate` from `earningsAverage`, filtered to the `[from, to]` window; ETFs and indexes have no fundamentals and simply produce no row. A 429 is retried once after 500 ms; a failure for one symbol is logged and skipped unless every symbol fails. Limits: Yahoo's data is unofficial and may change or rate-limit without notice; US exchanges only in search; no exchange-holiday calendar (a `1d` query during a holiday returns an empty session); Yahoo caps intraday history (`1m` to about 7 days, `5m`/`15m`/`1h` to 60 days), so long ranges at fine intervals fail per symbol; the live partial bar is included when it has a close. Tests replay fixtures recorded by `scripts/record.ts` under `test/fixtures/` and never touch the network; `pnpm smoke` runs the four kinds live for MU, NVDA, and SPY.

## v1.2 fallbacks (2026-10-18)

The connector also answers `profile`, `metrics`, `estimates`, `eps_history`, `dividends`, `insiders`, `institutions`, `short_interest`, `options`, and `holdings`, so these kinds still work when the OpenBB connector is not running. One module per kind under `src/`, each a `makeX(client)` factory behind the same client seam, fanned out per symbol with the same log-and-skip rule. Sources and unit decisions, all from `quoteSummary` unless noted:

| Kind | Yahoo source | Notes |
|---|---|---|
| `profile` | `assetProfile`, `price`, `summaryDetail`, `defaultKeyStatistics` | `exchange` is `price.exchangeName` (NasdaqGS, NYSEArca). ETFs have null sector, industry, employees and market cap; `beta` falls back to the fund's `beta3Year`. |
| `metrics` | `summaryDetail`, `defaultKeyStatistics`, `financialData`, `price` | Margins, growth, ROE are Yahoo fractions × 100. `debt_to_equity` is Yahoo's percent-form `debtToEquity` ÷ 100 (78.4 → 0.784), so it is a ratio like `pe` and `pb`. `dividend_yield` is checked against `dividendRate / price` because Yahoo has shipped `dividendYield` both as a fraction and as a percent; funds use `yield`. |
| `estimates` | `financialData`, `earningsTrend` | `upside_pct` is `(targetMeanPrice − currentPrice) / currentPrice × 100`; EPS estimates are the `0q` and `0y` trend rows; `eps_growth_y` is the `0y` estimate growth × 100. `recommendation` is Yahoo's key (`strong_buy`, `buy`, `hold`, `underperform`, `sell`). |
| `eps_history` | `earningsHistory` | Last four quarters only, newest first; `surprise_pct` × 100; `date` is the fiscal quarter end (UTC date of the 00:00Z stamp). |
| `dividends` | `chart` with `events: 'div'` | One monthly-bar chart call per symbol over 30 years (events are independent of the interval); `ex_date` is the New York date of the event; no events is an empty answer, not a failure. |
| `insiders` | `insiderTransactions` | `action` from the filing text (Sale → sell, Purchase → buy, Award/Grant → grant, gifts and conversions → other); `price` is the quoted price, or `value / shares` when the text gives a range; `url` is null (Yahoo's `filerUrl` is empty). |
| `institutions` | `institutionOwnership` | Yahoo lists ten holders, largest first; `change_pct` is `pctChange` × 100. |
| `short_interest` | `defaultKeyStatistics` | One row (the latest settlement), so `limit` is moot. `change_pct` is against `sharesShortPriorMonth`, which yahoo-finance2 mistypes as a Date (the share count arrives as a seconds-epoch Date and is converted back); `avg_volume` is `sharesShort / shortRatio`, the basis of Yahoo's days to cover. |
| `options` | `options()` | The first call lists every expiration with the nearest chain; another expiration costs a second call with `date`. Expiration rule as in the catalog (snap forward; omitted means ≥ 7 days out, else ≥ 1 day). The strike window is the `strikes` nearest listed strikes below and at-or-above `quote.regularMarketPrice` from the union of call and put strikes. `iv` × 100; no greeks (null); `dte` in calendar days from today in New York. |
| `holdings` | `topHoldings` | Top ten only; `weight` is `holdingPercent` × 100. A non-fund has no module and throws so the registry falls back. |

Not answered here: `financials` (Yahoo's statement modules are empty since 2024 and `fundamentalsTimeSeries` is out of scope), `volatility`, `calendar`, `ipos`, `movers`, `macro`, `yield_curve`. Fixtures for these kinds come from `scripts/record-catalog.ts` (`summaryModules.json`, `options.json`, `dividends.json`, trimmed to the fields read); `pnpm smoke` also runs them live.
